# My Planner — برنامه‌ریز شخصی

> یک وب‌اپلیکیشن سبک و کاربردی برای برنامه‌ریزی فعالیت‌های روزانه، مدیریت زمان، ثبت دستاوردها و مشاهده روند پیشرفت.
> **تسک اول کارآموزی وب** — پیاده‌سازی‌شده با HTML/CSS/JavaScript، Python/FastAPI و SQLite.

---

## ۱. معرفی کوتاه

**My Planner** یک برنامه‌ریز شخصی تحت وب است که به شما کمک می‌کند فعالیت‌های روزانه‌تان را در حوزه‌های مختلف (برنامه‌نویسی، زبان انگلیسی، هوش مصنوعی، مطالعه، ورزش، کارهای شخصی و...) سازمان‌دهی کنید، برای هر فعالیت زمان برنامه‌ریزی کنید، زمان واقعی صرف‌شده را با تایمر ثبت کنید و در پایان روز یا هفته گزارش عملکرد و پیشرفت خود را ببینید.

این پروژه در قالب یک **معماری ساده و کلاسیک وب** ساخته شده است:

```
Frontend (HTML/CSS/JS)  →  API (FastAPI)  →  Backend (Python)  →  Database (SQLite)
```

تمام اطلاعات به‌صورت **محلی** روی کامپیوتر خود شما در یک فایل SQLite ذخیره می‌شود. برای اجرای آن به هاست، دامنه، حساب کاربری آنلاین یا API Key نیاز نیست.

## ۲. هدف و کاربرد

هدف این پروژه ساخت یک ابزار شخصی واقعی است که در زندگی روزمره و مسیر یادگیری قابل استفاده باشد. My Planner به‌جای «فقط تیک‌زدن کارها»، به این پرسش‌ها پاسخ می‌دهد:

- امروز چه کارهایی داشتم و کدام‌ها را انجام دادم؟
- برای هر کار چقدر زمان در نظر گرفته بودم و واقعاً چقدر زمان صرف شد؟
- در این هفته در هر حوزه (مثلاً برنامه‌نویسی یا زبان) چه پیشرفتی داشته‌ام؟
- نتیجه و دستاورد هر فعالیت چه بود؟

## ۳. مسئله‌ای که حل می‌کند

کاربر به‌طور هم‌زمان چندین مهارت و فعالیت را دنبال می‌کند. ابزارهای پراکنده (یادداشت، تقویم، تایمر جدا) باعث می‌شوند در پایان هفته ندانید وقت‌تان کجا رفته است. My Planner همه این‌ها را در یک محیط واحد جمع می‌کند:

- فهرست فعالیت‌ها با دسته‌بندی
- برنامه‌ریزی زمانی (تاریخ، ساعت، مدت مورد انتظار)
- ثبت زمان واقعی با تایمر پایدار
- ثبت دستاورد
- گزارش روزانه و هفتگی و مقایسه برنامه با عملکرد

## ۶. معماری کلی و نحوه ارتباط اجزا

```
┌────────────────┐     HTTP/JSON      ┌──────────────┐     SQL      ┌──────────┐
│   مرورگر کاربر  │  ───────────────▶  │   FastAPI    │  ─────────▶  │  SQLite  │
│  HTML/CSS/JS   │  ◀───────────────  │   (Python)   │  ◀─────────  │  .db     │
└────────────────┘    پاسخ JSON        └──────────────┘    داده       └──────────┘
      فرانت‌اند                            بک‌اند                       دیتابیس
```

**مثال واقعی — وقتی کاربر یک فعالیت جدید ثبت می‌کند:**

1. کاربر فرم «فعالیت جدید» را در `frontend/index.html` پر و روی «ذخیره» کلیک می‌کند.
2. تابع `submitTask` در `frontend/script.js` یک درخواست `POST /api/tasks` با بدنه JSON می‌فرستد.
3. FastAPI در `backend/main.py` درخواست را دریافت می‌کند، آن را با مدل `TaskIn` (Pydantic) اعتبارسنجی می‌کند.
4. در صورت معتبر بودن، تابع `create_task` در `backend/database.py` فراخوانی می‌شود.
5. این تابع یک دستور `INSERT` روی جدول `tasks` در فایل `planner.db` اجرا می‌کند.
6. فعالیت ذخیره‌شده به‌صورت JSON به فرانت‌اند برگردانده می‌شود.
7. JavaScript نتیجه را می‌گیرد، فهرست را دوباره می‌سازد و فعالیت جدید در صفحه ظاهر می‌شود.

**مثال تایمر:** دکمه «شروع» درخواست `POST /api/tasks/{id}/timer/start` می‌فرستد. بک‌اند زمان شروع را (به UTC) در ستون `timer_started_at` ذخیره می‌کند. فرانت‌اند با اختلاف زمان فعلی و زمان شروع، عدد تایمر را هر ثانیه به‌روز می‌کند. چون زمان شروع در **دیتابیس** ذخیره شده، با Refresh یا بستن مرورگر از بین نمی‌رود.

```
Personal-Planner-T1/
│
├── frontend/                  ← بخش فرانت‌اند (سمت کاربر)

│   ├── database.py            ساخت دیتابیس و تمام عملیات خواندن/نوشتن (CRUD)
│   └── planner.db             دیتابیس SQLite (خودکار در اولین اجرا ساخته می‌شود)

├── .gitignore                 فایل‌هایی که نباید منتشر شوند
├── README.md                  همین فایل (شناسنامه و راهنمای پروژه)
├── INSTALL.md                 راهنمای کوتاه نصب و اجرا
├── LEARNING-NOTES.md          سند آموزشی گام‌به‌گام برای یادگیری
├── UI-UX-DOCUMENT.md          سند طراحی رابط و تجربه کاربری
└── DEVELOPMENT-JOURNEY.md     مسیر توسعه پروژه از نیازمندی تا تحویل
```

**نقش هر فایل:**

- **`frontend/index.html`**: اسکلت صفحه و همه بخش‌ها. اگر نباشد، صفحه‌ای وجود ندارد.
- **`frontend/style.css`**: ظاهر و چیدمان. اگر نباشد صفحه کار می‌کند اما بدون طراحی و به‌هم‌ریخته است.
- **`frontend/script.js`**: منطق تعامل و ارتباط با سرور. اگر نباشد، دکمه‌ها هیچ کاری نمی‌کنند.
- **`backend/main.py`**: پل بین وب و داده. اگر نباشد مرورگر نمی‌تواند اطلاعات را بخواند/ذخیره کند.
- **`backend/database.py`**: مدیریت داده. اگر نباشد هیچ اطلاعاتی ذخیره نمی‌شود.
- **`planner.db`**: محل نگهداری داده‌ها. در اولین اجرا خودکار ساخته می‌شود.

## ۹. راهنمای گام‌به‌گام اجرا (Windows)

### روش ساده (پیشنهادی — بدون نصب هیچ‌چیز)

1. پوشه پروژه را از حالت فشرده خارج کنید (پوشه `python/` حتماً همراه بقیه فایل‌ها باشد).
2. روی فایل **`start.bat`** دوبار کلیک کنید. سرور اجرا و چند ثانیه بعد مرورگر روی آدرس زیر باز می‌شود:

   ```
   http://127.0.0.1:8000
   ```

3. برای **توقف سرور**، در پنجره سیاه‌رنگ کلیدهای `Ctrl + C` را بزنید (یا پنجره را ببندید).

> **نکته:** `setup.bat` فقط زمانی لازم است که پوشه `python/` موجود نباشد؛ در آن حالت به پایتون نصب‌شده روی سیستم (نسخه ۳٫۱۰ یا بالاتر) و یک‌بار اینترنت نیاز است.

### روش دستی (در ترمینال VS Code)

```powershell
# ۱) رفتن به پوشه پروژه
cd Personal-Planner-T1

# ۲) ساخت محیط مجازی
py -m venv .venv

# ۳) فعال‌سازی محیط مجازی
.\.venv\Scripts\Activate.ps1
# (اگر با خطای اجرای اسکریپت مواجه شدید، یک بار این را اجرا کنید:
#  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned )

# ۴) نصب وابستگی‌ها
pip install -r requirements.txt

# ۵) اجرای برنامه
python backend\main.py

# ۶) در مرورگر آدرس زیر را باز کنید
#    http://127.0.0.1:8000
```

> **نکته مهم:** فرانت‌اند را مستقیماً با دوبار کلیک روی `index.html` (آدرس `file://`) باز نکنید؛ چون JavaScript در آن حالت نمی‌تواند با API ارتباط برقرار کند. برنامه باید از طریق سرور محلی اجرا شود. (با `start.bat` این کار به‌صورت خودکار انجام می‌شود.)

## ۱۰. نحوه استفاده از امکانات اصلی

1. **داشبورد امروز:** پس از ورود، خلاصه امروز (تعداد فعالیت، انجام‌شده، زمان برنامه و زمان واقعی) و حلقه پیشرفت را می‌بینید.
2. **افزودن فعالیت:** روی دکمه «＋ فعالیت جدید» بزنید، عنوان، دسته‌بندی، تاریخ، ساعت، مدت مورد انتظار و وضعیت را وارد کنید.
3. **شروع تایمر:** روی «▶ شروع» یک فعالیت بزنید. تایمر شروع می‌شود و بالای صفحه نمایش داده می‌شود. با «⏸ توقف» متوقف می‌شود.
4. **ثبت دستاورد:** در فرم ویرایش فعالیت، فیلد «دستاورد / نتیجه» را پر کنید.
5. **تغییر وضعیت:** با «✓ انجام شد» فعالیت به‌عنوان انجام‌شده علامت می‌خورد.
6. **گزارش‌ها:** به بخش «گزارش‌ها» بروید؛ گزارش روزانه، نمودار هفتگی (برنامه در برابر واقعی) و عملکرد هر دسته‌بندی را ببینید.
7. **دسته‌بندی‌ها:** در بخش «دسته‌بندی‌ها» می‌توانید دسته جدید بسازید یا دسته‌های موجود را ویرایش/حذف کنید.

## ۱۱. محدودیت‌های نسخه فعلی

- **بدون ورود کاربر / چند کاربر:** برنامه برای استفاده شخصی تک‌کاربره طراحی شده است.
- **گزارش بر اساس «تاریخ برنامه‌ریزی»:** اگر کاری را در روز دیگری انجام دهید، در گزارش همان روز برنامه‌ریزی‌شده محاسبه می‌شود.
- **فقط یک تایمر فعال در هر لحظه:** شروع تایمر جدید، تایمر قبلی را متوقف می‌کند (برای جلوگیری از ثبت اشتباه).
- **بدون هوش مصنوعی:** طبق نیازمندی، هیچ مدل AI استفاده نشده است.
- **بدون تشخیص خودکار فعالیت از روی نرم‌افزارهای باز:** زمان فقط با تایمر یا ثبت دستی محاسبه می‌شود.
- **بدون تقویم پیشرفته، عادت‌ها (Habit) و اهداف بلندمدت:** در نسخه‌های آینده.

### ج) مواردی که نیاز به بررسی دستی توسط شما دارند

این موارد با اجرای خودکار مرورگر آزمایش **نشده‌اند** و بهتر است خودتان یک‌بار بررسی کنید:

- کلیک واقعی روی دکمه‌ها در مرورگر (افزودن، ویرایش، حذف، شروع/توقف تایمر).

- عملکرد نمودار هفتگی و گزارش‌ها از دید کاربر.

> داده‌های آزمایشی: در جریان آزمایش، یک فعالیت نمونه («Test add task») ساخته و در پایان **حذف** شد. دیتابیس تحویلی خالی است و در اولین اجرا تازه ساخته می‌شود.

## ۱۳. پشتیبان‌گیری و بازیابی دیتابیس

کل اطلاعات برنامه در یک فایل به نام **`backend/planner.db`** ذخیره می‌شود.

**پشتیبان‌گیری:**

1. برنامه را متوقف کنید (`Ctrl + C`).
2. فایل `backend/planner.db` را کپی کنید و مثلاً به نام `planner-backup-1405-08-21.db` جایی نگه دارید.

یا در ترمینال:

```powershell
copy backend\planner.db backend\planner-backup.db
```

**بازیابی:**

1. برنامه را متوقف کنید.
2. فایل پشتیبان را روی `backend/planner.db` کپی کنید (جای‌گذاری کنید).
3. برنامه را دوباره اجرا کنید.

> این پروژه فقط از کتابخانه استاندارد `sqlite3` استفاده می‌کند و هیچ ابزار خارجی برای پشتیبان‌گیری لازم نیست.

## ۱۴. رفع اشکالات رایج

| مشکل | راه‌حل |
|------|-------|
| `'python' is not recognized` | از دستور `py` استفاده کنید یا Python را با گزینه «Add to PATH» نصب کنید. |
| `ModuleNotFoundError: No module named 'fastapi'` | ابتدا `setup.bat` را اجرا کنید یا `pip install -r requirements.txt`. |
| صفحه باز می‌شود اما داده‌ای نشان نمی‌دهد | مطمئن شوید سرور در حال اجراست و از `http://127.0.0.1:8000` باز کرده‌اید، نه `file://`. |
| `Address already in use` (پورت اشغال) | یک نمونه دیگر سرور در حال اجراست؛ آن را ببندید یا پورت را در `backend/main.py` تغییر دهید. |
| متن فارسی در ترمینال به‌هم‌ریخته است | مشکل نمایشی کنسول ویندوز است و به داده‌ها آسیبی نمی‌زند؛ داده‌ها درست ذخیره می‌شوند. |
| اجرای اسکریپت فعال‌سازی در PowerShell مسدود است | یک بار دستور `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` را اجرا کنید. |
